# SteamMonitor 架构说明

本文记录 0.8 重构后的代码结构和模块边界，方便后续开发时判断代码该放在哪里。产品功能和界面规划见 [设计规划](设计规划.md)。

## 进程与数据流

```text
┌──────────── 主进程 (Node + Electron) ─────────────┐        ┌────── 渲染进程 (React, sandbox) ──────┐
│ index.ts      生命周期：单实例、窗口、托盘、退出    │        │ main.tsx → app/app.tsx               │
│ runtime.ts    Runtime：模式、暂停、休眠、各采集器   │  IPC   │ pages/*      各页面                  │
│ ipc/*         按领域分组的请求处理 + 参数校验      │◀──────▶│ components/* 通用组件                │
│ collect/*     定时任务：状态轮询、好友发现、时长采样 │ invoke │ lib/*        api、格式化、视图模型    │
│ data/*        SQLite 存储、统计、演示数据、CSV      │ change │                                      │
│ steam/*       Steam Web API、游戏素材缓存           │        └──────────────────────────────────────┘
│ notify/*      通知规则 + Windows 系统通知           │                 ▲
│ update/*      界面热更新、GitHub 发布检查           │                 │ preload.ts (contextBridge)
│ shell/*       窗口、托盘、steam-art:// 协议         │─────────────────┘
└───────────────────────────────────────────────────┘
                 │                 shared/ ← 两端共用的类型和纯函数
                 ▼
     %APPDATA%\SteamMonitor\history.sqlite / game-assets.sqlite / steam-key.enc / ui-updates/
```

- 渲染进程只能通过 `window.monitor`（`MonitorApi`）访问主进程。每个方法对应一个 `monitor:<方法名>` 通道，另有一个推送通道 `monitor:change`，渲染进程收到后重新读取快照。
- 主进程只接受来自主窗口主框架的请求（`ipc/register.ts`），所有参数在 `ipc/validate.ts` 或各处理函数中重新校验。

## 目录

```text
src/
  shared/                 主进程、preload、渲染进程共用
    types.ts              数据类型与 MonitorApi 契约（只放类型）
    domain.ts             isGameAppId、presenceLabels、isApiKey
    consent.ts            授权确认文字（界面显示与主进程留档共用）
    gap-display.ts        缺口收起与色带合并规则（时间轴和统计共用）
    game-names.ts         官方中文游戏名补充
    index.ts              统一出口
  main/
    index.ts              应用入口，只做装配
    runtime.ts            Runtime：进程级状态与协调（syncPolling、setMode、snapshot…）
    paths.ts              构建产物路径、用户数据文件名、开机启动参数
    credentials.ts        KeyVault：API Key 加密读写
    preferences.ts        设置校验
    preload.ts            contextBridge 桥接（只能 require electron）
    ipc/                  register.ts 汇总；collection / consents / friends / history / playtime / settings / updates 分组
    collect/              poller.ts（60 秒状态采样）、discovery.ts（好友发现）、playtime.ts（公开时长采样）
    data/                 store.ts（SQLite）、migrations.ts（结构版本与迁移）、analytics.ts（时段、统计）、csv.ts、demo.ts
    steam/                api.ts（Web API 客户端与数据规范化）、artwork.ts（游戏名与图标缓存）
    notify/               rules.ts（上线、开玩、凑人规则）、desktop.ts（Windows 通知）
    update/               ui-update.ts（打包、校验、暂存）、github-update.ts、ui-host.ts（试运行与回滚）
    shell/                window.ts、tray.ts、art-protocol.ts
  ui/
    main.tsx              挂载 React，引入全局样式
    app/                  app.tsx（路由、页面保活、滚动和焦点恢复）、workspace.tsx（侧栏、采集状态、横幅）
    pages/
      friends/            好友页、好友详情、添加与编辑弹窗、发现提示
      onboarding/         首次使用引导（三步弹窗）
      activity/           活动页、泳道图与概览、activity.css
      timeline/           单个好友横向时间轴、时长对比实验
      review/             回顾页
      settings/           设置页、软件更新、好友发现、通知与数据管理
    components/           图标、头像与游戏图、徽标、空状态与横幅、弹窗与步骤条、授权记录、事件列表、时间轴色带、缺口控件、统计面板
    lib/                  api.ts、format.ts、model.ts、game-titles.ts、motion.ts、timeline-navigation.ts、use-report.ts
    styles/               tokens.css（设计令牌）、base.css、workspace.css、motion.css
tests/                    node:test，运行 build/ 下的编译结果；fixtures/ 存放旧版本库结构
  ui/                     界面冒烟测试（playwright-core 启动 Electron）
scripts/                  Windows 打包与发布
docs/                     计划书、设计提案、本文、设计规划
sdk-probe/                Steamworks 好友视角验证探针（独立 C++ 工具）
```

## 约定

| 事项 | 约定 |
| --- | --- |
| 新增 IPC 方法 | 在 `shared/types.ts` 的 `MonitorApi` 加签名，在 `ipc/` 对应分组实现，在 `preload.ts` 的 `methods` 列表加名字。主进程的 `MonitorHandlers` 类型和 preload 的完整性检查会在漏写时编译失败。 |
| 依赖方向 | `shared` 不依赖任何一端。`main/data`、`main/steam` 不依赖 Electron，可直接在 node:test 中运行。Electron API 只出现在 `index.ts`、`runtime.ts`、`credentials.ts`、`ipc/`、`shell/`、`notify/desktop.ts`、`update/ui-host.ts`。 |
| 界面热更新 | `update/ui-update.ts` 的后端指纹覆盖 `build/` 下除 `ui/` 外的全部 `.js`（含子目录）。主进程、preload 或 shared 有任何改动都会让旧界面包失效，必须发布完整版本。 |
| 时间 | 入库为 UTC 毫秒；界面按本机时区显示。按日回顾按本地零点切分。 |
| 样式 | 颜色、字号、字重、圆角、间距只在 `styles/tokens.css` 定义，其他样式文件和组件一律引用令牌（SVG 里用 `var(--…)`）。界面保持单色，彩色只用于状态和色带，规则见设计规划 5.1。 |
| 文案 | 界面与错误提示使用简体中文；错误信息从主进程抛出后由 `lib/api.ts` 的 `errorText` 去掉 Electron 前缀。 |
| 数据库结构 | 版本记录在 `PRAGMA user_version`。改结构时在 `data/migrations.ts` 的 `migrations` 数组**末尾追加**一步，不修改已发布的步骤，也不在别处写「不存在就创建」。每一步与版本号在同一事务内提交；库的版本比程序新时拒绝打开。 |
| 备份恢复 | 备份是不可信文件：结构必须与它自己版本的已知结构一致（0.8 之前的无版本备份按旧结构规则核对），数据先在内存库里跑同一套迁移，再导入。新增需要随备份恢复的表时加入 `store.ts` 的 `backupTables`。 |
| 授权 | 开始记录、时长采样、好友发现都由主进程校验勾选并写入 `consents` 表，文字取自 `shared/consent.ts`。撤回会停止对应采集；撤回后再次开启必须重新确认。 |
| 检查 | `npm test` 编译主进程并运行单元测试；`npm run build` 额外做渲染进程类型检查（`noUnusedLocals` 开启）并打包；`npm run test:ui` 构建后用 playwright-core 启动 Electron（`--no-sandbox`、独立用户数据目录），在演示模式下走一遍引导、四个页面和时间轴，控制台有错误即失败。CI（`.github/workflows/ci.yml`）在 push 和 PR 时运行这三项。 |
